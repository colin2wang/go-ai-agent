我没法直接看到你的截图（`SCREENSHOT.md` 里的图片未随文档提供），但从项目文档能确认几个关键现状：`styles.css` 是"浅色卡片式，**绿/蓝/紫/橙强调色**"，页面由 MetricCard / TrendChart / Sparkline 指标卡构成，且已有 `theme.ts` 和一个 `terminal` 暗色主题。基于这个基础，下面给出完整的重设计方案。
---
## 一、先对号入座：你的项目里能确认的"AI 味"信号
社区现在对 AI 生成界面的特征已有相当成熟的总结（Tailwind `indigo-500` 渐变、Inter 字体、图标彩底三栏卡片等都是典型来源）。对照你的项目：
| 信号 | 你项目中的对应 | 严重度 |
|---|---|---|
| **一屏多强调色** | 绿/蓝/紫/橙四色强调色，每个 MetricCard 一个色 | ★★★ 最典型 |
| 彩色图标底 | 指标卡/功能卡的圆形彩色图标背景 | ★★★ |
| 统一大圆角 + 柔阴影 | "卡片式"布局通常伴随 16px 圆角 + 多层阴影 | ★★ |
| 渐变图表 | TrendChart/Sparkline 若有渐变填充、彩色圆点 | ★★ |
| emoji 当图标 | AppIcon / 菜单项 / 空状态 | ★★ |
| 装饰性文案 | "智能解析""一键搞定"类描述 | ★ |
| 等宽卡片网格 | 概览页四张等宽 MetricCard + 图表卡 | ★ |
去 AI 味的本质不是"换个配色"，而是做三件减法：**颜色只表达状态、密度对齐工具类应用、质感靠边框和字体而非阴影渐变**。
---
## 二、确立方向：你有两条路，推荐第二条
**路线 A：克制型 SaaS 风**（Linear / Vercel Dashboard 那种）——暖灰中性色 + 单强调色，能及格，但依然容易做得"干净而平庸"。
**路线 B：把已有的 `terminal` 主题升格为整个应用的视觉语言** ⭐ 推荐。理由：
1. `theme.ts` 里已经有 terminal 暗色主题，说明审美方向本来就在这里；
2. 你的产品是**本地 LLM 工作台**（工资单 OCR、目录识别、字幕批处理），用户操作的是文件、JSON、token 数——本质是工程工具，不是消费级 App；
3. terminal 美学天然免疫 AI slop：直角/小圆角、1px 边框、mono 数字、单色调，没有渐变和毛玻璃的生存空间。
   落地后是"**浅色为主、边框驱动、mono 数字**"的工作台风格——类似 Zed 编辑器浅色主题 + Grafana 的密度感。
---
## 三、Design Tokens：`styles.css` 重写核心
```css
:root {
  /* 中性色：暖灰，避免 slate 的蓝调（蓝灰 = AI 味） */
  --bg:            #FAF9F7;   /* 页面底，微暖 */
  --surface:       #FFFFFF;   /* 卡片/面板 */
  --surface-2:     #F4F2EF;   /* 次级面板、表头 */
  --border:        #E3E0DA;
  --border-strong: #C8C4BC;
  --text:          #1D1B18;
  --text-2:        #56524B;   /* 次级文字，保持 ≥4.5:1 对比度 */
  --text-3:        #8B857B;   /* 仅限"可跳过"信息（时间戳、ID） */
  /* 单一强调色：深青绿。避开 indigo/purple/默认蓝 */
  --accent:        #0E7A6C;
  --accent-hover:  #0B6357;
  --accent-bg:     rgba(14,122,108,.07);  /* 选中态底色 */
  /* 语义色只用于状态，永不用于装饰 */
  --ok:      #2B7A3D;
  --err:     #C2352B;
  --warn:    #9A6700;
  --running: #3556C8;
  /* 形状分级：不是"万物一个圆角" */
  --r-sm: 4px;   /* 按钮、输入框、tag */
  --r-md: 6px;   /* 卡片 */
  --r-lg: 10px;  /* 仅弹窗、下拉浮层 */
  --shadow-pop: 0 4px 16px rgba(29,27,24,.10);  /* 唯一的阴影，只给浮层 */
  /* 字体：Windows + Wails(WebView2) 直接吃系统栈，零网络依赖 */
  --font-ui:   "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif;
  --font-mono: "Cascadia Code", "Consolas", monospace;  /* Win11 自带 Cascadia */
}
/* terminal 暗色主题同构一套变量即可，两套主题共享组件样式 */
[data-theme="terminal"] {
  --bg: #121412; --surface: #191C19; --border: #2A2E2A;
  --text: #D6D9D4; --accent: #5BB89B; /* ... */
}
```
配套的全局规则：
```css
/* 数字全部 mono + 表格对齐，这是"工程感"的最大来源 */
.num, td.num, .metric-value {
  font-family: var(--font-mono);
  font-variant-numeric: tabular-nums;
}
/* hover 只做背景/边框变化，禁止上浮+阴影加深 */
.btn:hover { background: var(--surface-2); }
.card:hover { border-color: var(--border-strong); }
/* transition ≤150ms，删掉所有 ease-out-back 弹性曲线 */
* { transition-duration: 120ms; }
@media (prefers-reduced-motion: reduce) {
  * { transition: none !important; animation: none !important; }
}
```

## 四、逐组件改造清单
### `Sidebar.vue`
- 宽度收到 216px；顶部 App 名用普通字重，不要渐变 logo；
- 图标换成**一套线性图标**（推荐 lucide，1.5px 描边，可按需拷贝 SVG 内联进 `AppIcon.vue`，不引运行时库），彻底清掉 emoji；
- 当前项：左侧 2px `--accent` 竖条 + `--accent-bg` 浅底，**不要**整块彩底圆角胶囊；
- 每个功能项右侧可以加 mono 小字标注类型（`chat` / `ocr`），比彩色小圆点有信息量。
### `MetricCard.vue`（去 AI 味的性价比最高）
```
改造前（slop 结构）：  [彩色圆底图标]  调用量        1,234
                       ↑ 渐变数字 ↑ 彩色边框
改造后：
  调用量（text-2 小标签，不加图标）
  12,431        ← --font-mono，28px，--text
  ↑ 8.2% 较昨日  ← delta 用语义色，只在这一处用色
```
- **删掉图标底、渐变数字、彩色顶边条**；
- 核心提升：显示 **delta（环比变化）**而不是裸快照——仪表盘的可信度来自趋势而非绝对值；
- 四张卡等宽没问题，但卡片间用**共用边框的分组**（一张表嵌四个 cell，共享 1px 分隔线）比四张独立阴影卡密度高得多。
### `TrendChart.vue` / `Sparkline.vue`
- 1.5px 单色线（`--accent` 或 `--text-2`），**删渐变面积填充、删数据点圆点**（hover 才显示）；
- 网格线只留横向，用 `--border`；
- 或者换成**细竖条图**（2px 宽 bar，像 Stripe 用量图）——比折线更"后台工具"。
### `OverviewView.vue`
- "最近调用"和"模型用量"**从卡片改为表格**：模型名列用 mono，数字列右对齐 `tabular-nums`，状态列用文字 `done` / `failed`（mono 小写），可以配 6px 色点但语义全站统一；
- 端点连通性做成表格内嵌行：`lmstudio-local  ✓ ok  42ms  [测试]`（ghost 按钮），删掉彩色状态大卡；
- 页头：标题左、时间范围切换（7d/14d/30d）右，用 segmented control 而不是下拉。
### `ChatView.vue`
- 气泡去彩虹：用户消息 `--surface-2` 底 + `--r-sm` 圆角；**AI 回复不要气泡**，直接平铺排版（和 Claude/ChatGPT 网页版一致）——气泡套气泡是聊天 UI 的最大 AI 味来源；
- 气泡底部 meta 行（端点/模型/token/耗时）用 `--font-mono` 11px `--text-3`，如 `qwen3-vl-8b · 1.2k tok · 3.4s`；
- 流式输出保留光标闪烁（这是**功能性**动效，不是装饰）；思考链区域用左边 2px 边框 + `--text-2` 区分；
- 输入框：1px 边框，focus 时边框变 `--accent`，**禁止** focus glow/外圈光晕。
### `FeatureView.vue`（工作流执行页）
- 上传区：虚线 1px 边框，hover 边框变 `--accent`，删掉所有背景渐变光斑；
- pipeline 步骤条改成紧凑形式：`ocr ─▶ merge ─▶ render`（mono 小写 + 细线连接），当前步骤 `--accent`，完成的打勾，**不要**彩色圆形图标 + 大箭头的"可爱风"；
- 进度显示用**细进度条**（3px，纯色）或 mono 文本 `ocr 3/8`，不用转圈 spinner；
- structured JSON 结果：mono 代码块 + 顶栏复制按钮，字段表用表格，这是你产品的核心输出，值得做出质感。

## 五、文案层（零成本、见效快）
- 全局清除 emoji；
- 删除"智能 / 一站式 / 赋能 / 强大"，换成可验证的具体陈述：
    - ~~"智能解析工资单，一键搞定"~~ → "上传工资单截图，提取 24 项工资字段并合并为 JSON"
    - ~~"开始智能翻译之旅"~~ → "翻译字幕"
- 功能描述直接写输入输出（你 `features/*.yml` 里的 description 已经写得不错，前端照搬即可）；
- 空状态写清下一步动作："还没有调用记录——先在 ai.yml 配置一个端点"，而不是插画 + "这里空空如也 ✨"。
